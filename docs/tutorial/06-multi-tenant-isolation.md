# 06 · 多租户与行级隔离

> 前置：[05 权限模型](./05-permission-model.md)。读完你会理解："行级谁的数据"——HTTP 闸门、数据层谓词、数据范围与套餐联动，以及新表接入隔离的清单。

## 1. 两道闸，各管一层

租户隔离不是一个点，是叠在两个层面的闸：

```text
HTTP 层（crates/auth::TenantAccessChecker）——"这个租户能不能用这个接口"
    │  按 (路径模板, method) 判定，403 信封拒绝
    ▼
数据层（services/admin-api/src/data/scope.rs::Viewer）——"这行数据是不是你的"
    │  每条 SQL 的谓词强制，查询/写入/删除全覆盖
    ▼
PostgreSQL
```

两层都过才有数据。只懂其中一层就会把"接口 403"和"列表为空"混为一谈。

## 2. HTTP 闸门：七步判定

租户登录（`tid > 0`）的每个请求按序过七步，任何一步失败即 403（`FORBIDDEN` 信封）：

| 步 | 判定 | 失败消息 |
|---|---|---|
| 1 | 租户行存在 | `access denied` |
| 2 | 状态 = ON | `tenant is not active` |
| 3 | 到期且套餐为只读策略 → **写方法拒绝**（GET/HEAD/OPTIONS 放行） | `tenant is read-only due to expiry` |
| 4 | (路径模板, method) 在 Api 表注册（**fail-closed**：未注册即拒） | `access denied` |
| 5 | 路由所属业务模块 ≠ UNSPECIFIED | `module not allowed` |
| 6 | 租户有套餐 | `no subscription plan` |
| 7 | 套餐模块白名单包含该模块 | `module not allowed` |

三个要点：

- **fail-closed 是基调**：第 4 步意味着新接口忘了注册 Api 表，租户侧一律 403——宁可拒不可漏；
- **到期只读是"写拒读通"**：过期租户还能登录看数据，但任何写方法被第 3 步拦下；
- 平台管理员（`tid = 0`）整段跳过——平台域不受租户闸门约束。

套餐侧数据模型：`sys_plans`（套餐）→ `sys_plan_modules`（模块白名单）+ `sys_plan_quotas`（用量上限）；租户到期由系统 cron（`tenant_expiry_scan`，每小时）扫描落状态。

## 3. 数据层：Viewer 三态

`src/data/scope.rs` 是**唯一**的租户判定点。每个仓储查询都从请求上下文取 `Viewer`，派生谓词：

| Viewer | 语义 |
|---|---|
| `Noop` | 无凭据（公开路由），只配白名单面 |
| `User (tid = 0)` | 平台视图：不加租户谓词，全租户行可见 |
| `User (tid > 0)` | 租户视图：查询/更新/删除强制 `tenant_id = tid`，创建强制盖章，跨租户写拒绝 |
| `System` | 系统视图：旁路全部租户谓词（启动种子、令牌清理等内部作业专用） |

由这个单点派生出的行为（不需要各仓储自觉）：

- 租户用户的任何 list/get/update/delete 都看不到、摸不到别家行——按 id 直查也逃不掉；
- 创建时 `tenant_id` 由服务端盖章，伪造租户字段无效；
- 子树/级联操作（如组织单元删除）在**语句级**携带谓词——混合租户的子树不会被越权删除。

## 4. 数据范围：角色级的行过滤

租户内部还有一层"哪些组织单元的数据可见"——角色的 `data_scope` 五档，登录时聚合进令牌（`ds` / `dss` / `dsu` 声明），仓储谓词消费：

| 档 | 语义 |
|---|---|
| ALL | 全租户 |
| SELF | 仅本人 |
| UNIT_ONLY | 本组织单元 |
| UNIT_AND_CHILD | 本单元及子树 |
| SELECTED_UNITS | 自定义组织单元集（`dsu` 携带） |

与 Viewer 的关系：**Viewer 先圈租户，数据范围在租户内再圈组织**——两层谓词叠加，不是二选一。

## 5. 租户开通与自证

新建租户时自动初始化三件套：根组织单元、默认角色模板、租户管理员账号——租户开箱即可登录管理自己的组织。租户管理员再往下建部门、角色、用户，全部落在第 3 节的谓词覆盖之下。

## 6. 新表接入租户隔离的清单

1. 实体带 `tenant_id` 列（全局表除外），注册进 `migration.rs`；
2. 仓储经 Viewer 派生谓词（用既有仓储骨架，不自写裸查询）；
3. 路由的 (path 模板, method) 注册进 Api 表并归类业务模块；
4. 套餐若需管控该模块 → 模块进套餐白名单语义；
5. 台架/探针里加一条**跨租户访问用例**（A 租户令牌摸 B 租户行 → 应 404/403）。

## 7. 本章小结

- HTTP 闸门管"能不能用"，七步 fail-closed；数据层 Viewer 管"是不是你的"，谓词全覆盖；
- 到期只读、模块白名单、套餐配额是租户运营的三道商业闸；
- 平台/租户/系统三态是全部特权的来源，别在服务里另开旁路；
- 新表接入按清单走，跨租户用例是回归的必测项。
