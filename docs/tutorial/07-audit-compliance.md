# 07 · 审计与等保

> 前置：[01 架构全景](./01-architecture-overview.md)。读完你会知道：六类审计日志各记什么、在哪采集、怎么留存归档；身份鉴别三件套与 MFA 怎么用；能力边界在哪。

## 1. 六类审计日志

| 日志 | 表 | 记什么 | 采集点 |
|---|---|---|---|
| 登录日志 | `sys_login_audit_logs` | 成功/失败登录、IP 归属地、设备、**风控打分** | 认证服务 |
| 操作日志 | `sys_operation_audit_logs` | 操作类型、资源对象定位、请求快照、请求 ID | 审计中间件层 |
| API 日志 | `sys_api_audit_logs` | 操作者、路径、方法、成功状态 | 审计中间件层 |
| 数据访问日志 | `sys_data_access_audit_logs` | 数据访问行为、SQL 词法脱敏、涉及表名与数据分类 | 数据层 |
| 权限变更日志 | `sys_permission_audit_logs` | 权限变更的操作者、目标对象、原因、请求快照 | 权限服务 |
| 策略评估日志 | `sys_policy_evaluation_logs` | 每次鉴权判定的结果与上下文、trace_id | authz 评估器（[第 5 章](./05-permission-model.md)） |

审计层（`src/audit/`）挂在路由包上：认证放行后、handler 前后采集，业务代码零侵入；登录、权限变更等需要业务语义的日志由对应服务在动作点写入。

## 2. 登录风控打分

每次登录按启发式累计风险分并分档（LOW ≤ 30 < MEDIUM ≤ 70 < HIGH）：

| 信号 | 分值 |
|---|---|
| 登录失败 | +50 |
| 未知用户名 | +10（密码错）/ +20（用户不存在） |
| 缺设备标识 | +10 |
| 缺 IP | +5 |
| 内网来源 | −10 |

打分逻辑是纯函数（`src/audit/risk.rs`），输入输出都有单测钉住——调策略不改行为。

## 3. 操作日志的细节约定

- **动作映射**：操作类型按路由与语义映射（Create/Update/Delete/Query/**Assign/Unassign/Export/Import** 等），不是一律 OTHER——新增路由时对照动作映射表补臂；
- **目标定位**：从路径参数与请求体提取目标资源，日志能回答"谁对哪个对象做了什么"；
- **请求快照**：body 截断至 64 KiB 存档，配合请求 ID（三级回退生成）串起同请求的多类日志；
- **IP 字段优先级按日志类型区分**（登录类优先 XFF、鉴权类优先 X-Real-IP），这是线上契约的一部分，对齐基准见 [binding-spec.md](../binding-spec.md)。

## 4. 留存与归档

- 留存策略可调（默认库内留存 180 天），阈值走平台参数；
- 超期数据由系统 cron（`audit_log_archive`，每日 03:30）导出 JSONL 归档文件留痕后清理——归档本身也是一条可审计的动作。

## 5. 身份鉴别三件套（等保合规面）

| 要求 | 实现 | 调整入口 |
|---|---|---|
| 口令复杂度 | ≥8 位、小写/大写/数字/符号四类取三 | 平台参数（`sys_config`）热调 |
| 口令历史 | 默认近 3 条不可复用 | 同上 |
| 口令有效期 | 默认 90 天 | 同上 |
| 登录失败限流 | IP + 用户名双维度，5 次 / 15 分钟 | 代码常量（Redis Lua） |
| 图形验证码 | 每次登录校验，Redis 单次有效 | — |
| MFA | TOTP 绑定 + 登录挑战；管理员救援重置 | 个人中心 / 用户管理 |
| 口令保密 | 前端 AES 加密传输、bcrypt 存储、恒时假校验防枚举 | — |

等保 2.0 技术要求的完整对照表（含安全审计、访问控制、多租户隔离、数据保密性、备份恢复）见根 [README](../../README.md#安全与等保合规)；非软件范畴（管理制度、物理环境等）不在软件覆盖面内。

## 6. 边界与已知取舍

- 数据访问日志的采集面以数据层钩子为准，手工 SQL 与脚本内查询的覆盖以实现为准——使用前先确认你关心的事件在采集面内；
- 审计日志本身也是租户数据：平台视图看全部、租户视图只看自己的（Viewer 规则同[第 6 章](./06-multi-tenant-isolation.md)）；
- 审计写入与业务同事务语义的动作（如权限变更）在服务层落笔，保证"改了就有日志"。

## 7. 本章小结

- 六类日志分工明确：登录管"谁进来了"，操作/API 管"做了什么"，数据访问管"碰了哪些数据"，权限/策略评估管"权力怎么变的"；
- 风控打分、动作映射、请求快照、trace 关联是排障的四件利器；
- 鉴别三件套阈值全部热调，等保对照表在根 README；
- 动审计采集代码前，先跑打分与映射的既有单测。
